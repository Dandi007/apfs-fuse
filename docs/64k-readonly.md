# APFS 64 KiB 只读读取修复

## 需求与确认

2026-10-13 用户确认修复本机驱动并进行端到端只读验收。磁盘在 macOS 可读；禁止对盘写入、修复、格式转换或取消加密。目标为加密及未加密卷均可列目录并读取文件。本文不保存密码、密钥、用户文件名或内容。

## 设计

APFS 64 KiB 非根 BTree 节点的 value 区末尾为 65536，uint16_t 无法表示。将内存中 key/value 起点改为 size_t，磁盘结构保持原样。零初始化 tree info；根树初始化失败时拒绝挂载，迭代器遇空节点返回失败。补充 PList 的 cstdint include 以支持 GCC 15 构建。

只使用已有 C++ 类型和 CTest，无新增运行时依赖。不修改加密算法或校验规则，不启用 lax mode。

## 验收

合成测试覆盖 4 KiB/64 KiB、根/非根、fixed/variable 八种节点布局，核验映射值地址与内容，以及空树迭代返回失败。旧偏移类型应使回归测试失败；修复后 Debug/Release 测试通过。实盘验收在块设备 RO=1 下进行，以 FUSE ro,nodev,nosuid,noexec 挂载，验证目录和有限文件读取及重复哈希。

## 部署与发布条件

构建产物安装到本机独立版本目录，通过明确路径启动，不覆盖原驱动。挂载只在本次运行生效，不设置自动挂载。密码仅交互输入。通过测试、实盘验证并完成 PR 后达到 ready。回滚为卸载挂载点、停止使用修复二进制，磁盘无需任何回滚。

## 实测结果

Debug 与 Release 构建及 CTest 均通过。用原版类型运行同一测试，明确失败于 64 KiB value 地址检查。

实盘两个卷均解锁/挂载成功，根目录分别枚举 13 与 14 项。每卷读取 5 个普通文件；大文件读取头、中、尾各 1 MiB，小文件完整读取；两次 SHA-256 一致。此为抽样验收，不代表全盘数据完整性审计。磁盘与两个分区 RO=1，未执行任何写入试探。

文件路径、内容、凭据与具体设备标识不提交到仓库。
